# Кэшированный базовый образ через snapshot + перенос между машинами

## Суть
Сейчас `apply` каждый раз прогоняет полный `bootstrap.sh` (~20-30 мин на arm64: node, bun, loki, cline, skillkit). Добавим snapshot round-trip: команда `microcode build` один раз готовит VM и создаёт snapshot; затем `from_snapshot: <name>` в манифесте переиспользует его (`msb run --from-snapshot`), пропуская bootstrap. Плюс `save`/`load` для переноса snapshot между машинами (tar.zst архив).

## Механика microsandbox (из исходников msb)
- `msb snapshot create <NAME> --from <STOPPED-SANDBOX>` — захват (sandbox должен быть остановлен).
- `msb run --from-snapshot <NAME> --name <X> --detach` — запуск нового sandbox из snapshot (холодный бут новой VM с готовой ФС). Взаимоисключаемо с image. **Только на `msb run`, не на `msb create`.**
- `msb snapshot save <snap> <out.tar.zst> --with-image` — экспорт (с OCI-кэшем для офлайн-бута).
- `msb snapshot load <archive> [dest]` — импорт.

## Изменения по файлам

### 1. `manifest.py` — расширить `SnapshotConfig`
```python
class SnapshotConfig(BaseModel):
    enabled: bool = False                 # создать snapshot после bootstrap (build)
    name: str = "mcd-base"                # прежнее default "loki-prepared" -> переименовать
    from_snapshot: str | None = None      # переиспользовать готовый snapshot (apply)
    # валидатор: enabled и from_snapshot взаимоисключающи
```
`InitConfig.snapshot` уже есть. Добавить `model_validator`: нельзя одновременно `enabled=True` и `from_snapshot`.

### 2. `generators/sandbox.py` — две ветки
- **from_snapshot задан:** `_create_argv` эмиттит `msb run --from-snapshot <name> --name <sandbox> --detach ...` (ресурсы/сеть/monuts/порты/secrets те же). Bootstrap **пропускается** (init-команда не эмиттится). `--copy-file bootstrap.sh` НЕ нужен.
- **enabled (build):** текущее поведение (create + init + snapshot create).
- Добавить `_from_snapshot_argv(m)` helper.

### 3. `runners/sandbox_runner.py` — tolerate `msb run`
`_resolve_placeholders`: инжект cline-shim `--copy-file` только для `msb create` (уже так). Для `msb run --from-snapshot` bootstrap не нужен — shim уже в snapshot. Без изменений логики, но проверить что placeholder-резолвинг не падает на `msb run`.

### 4. Новая CLI-команда `build` (`cli.py`)
`microcode build [file]`:
1. doctor + plan.
2. msb create + bootstrap (init) — как apply, но **без skillkit и без loki**.
3. `msb stop <name>` (snapshot требует остановленный sandbox).
4. `msb snapshot create <snapshot.name> --from <name>`.
Реализуется переиспользованием `SandboxRunner` + `ShellRunner` для stop/snapshot.

### 5. Новые CLI-команды `snapshot save/load` (`cli.py`)
- `microcode snapshot save <name> <out.tar.zst>` → `msb snapshot save <name> <out> --with-image`.
- `microcode snapshot load <archive> [dest]` → `msb snapshot load <archive> [dest]`.
Тонкие обёртки, dry-run support.

### 6. `planner.py` / orchestrator
apply-flow: когда `from_snapshot` задан, sandbox-команды содержат только `msb run --from-snapshot` (без init). Orchestrator без изменений — он уже выполняет `plan.sandbox_commands` как есть.

### 7. `platform.schema.json`
`snapshot`: добавить `from_snapshot: string`; обновить default описания.

### 8. Тесты
- `from_snapshot` → plan содержит `msb run --from-snapshot`, НЕТ `bash bootstrap.sh`, НЕТ `--copy-file`.
- `enabled + from_snapshot` → validation error.
- `build` plan (dry-run) содержит create+init+stop+snapshot create.
- save/load argv корректны.
- Существующие 68 тестов зелёные.

### 9. Документация + пример
- README: подраздел "Cached base image (snapshots)" с циклом build → apply → save/load.
- ARCHITECTURE: apply-pipeline note про from_snapshot.
- `examples/cached-base.yaml`: `from_snapshot: mcd-base` + инструкция build один раз.

## Рабочий цикл пользователя
```bash
# один раз (создаёт кэш):
microcode build examples/cached-base.yaml
# → msb create debian + bootstrap.sh + msb stop + msb snapshot create mcd-base

# всегда потом (быстро, skip bootstrap):
microcode apply examples/cached-base.yaml
# → msb run --from-snapshot mcd-base --detach ... (skip bootstrap)

# перенос на другую машину:
microcode snapshot save mcd-base mcd-base.tar.zst
scp mcd-base.tar.zst host2:
microcode snapshot load mcd-base.tar.zst   # на host2
```

## Объём
manifest (SnapshotConfig) + sandbox generator (from_snapshot ветка) + cli (build/save/load команды) + schema + тесты + доки + пример. Без изменений в loki/skill runners.
