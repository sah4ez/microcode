# PRD 001: Refactoring Todo List Service (local storage) 

## Goal
Refactor A minimal todo-list REST service in this repository to golang service backend with saving
current API and implement on go and github.com/seniorGolang/tg as backend implementation. Need to write repository
to sqlite files. The previous implementation included a browser web UI — **it MUST be preserved**
(the Go service serves the same vanilla-JS UI alongside the API).

## Functional requirements
1. Create** a todo: `POST /todos` with `{"title": "...", "description": "..."}` →
   returns the created todo with `id`, `created_at`, `completed=false`.
2. **List** all todos: `GET /todos` → array of todos.
3. **Get** one: `GET /todos/{id}`.
4. **Update**: `PATCH /todos/{id}` — toggle `completed`, edit `title`/`description`.
5. **Delete**: `DELETE /todos/{id}`.
6. **Toggle complete**: `POST /todos/{id}/toggle`.

## Functional requirements — Web UI (MANDATORY)
The previous Python implementation shipped a browser UI; this refactor MUST
keep it. The Go service serves a vanilla-JS single-page UI from the same
process that serves the API:

- `GET /` → `static/index.html` (the UI page). Status 200.
- `GET /styles.css` → `static/styles.css`. Status 200.
- `GET /app.js` → `static/app.js`. Status 200.
- The UI is served by the **same** fiber app that owns the generated transport
  (call `srv.Fiber()` and register the three asset routes on it). Do NOT spin up
  a second HTTP server.
- The asset routes MUST be registered AFTER the `@tg` contract routes so they
  never shadow the API (`/todos...` wins, `/` and the two asset paths fall through).
- UI behavior (parity with the previous version):
  - Show the list of all todos (title, description, completed state, created_at).
  - A form to create a new todo (title required, description optional).
  - A "toggle" control that flips `completed` (calls `POST /todos/{id}/toggle`).
  - A "delete" control (calls `DELETE /todos/{id}`).
  - An inline "edit" mode for title + description (calls `PATCH /todos/{id}`).
  - Updates without a full page reload (fetch to `/todos...`).
- Stack for the UI: plain HTML + vanilla JS + minimal CSS. **No** React/Vue, **no**
  build step, **no** external CDN. One `index.html` + one `app.js` + one
  `styles.css`, all in `static/`.
- The UI talks to the REST API at `/todos` (NOT `/api/todos` — the old Python
  prefix is gone). Field names match the Go model: `title`, `description`,
  `completed`, `created_at` (NOT the old `body`/`done`).

## Non-functional requirements
- **Local persistence**: SQLite database file at `./data/todos.db` (auto-created).
- **Stack**: Go 1.26+, github.com/seniorGolang/tg/**v3** (the service/transport
  framework — **MANDATORY**, see below) + go-fiber + modernc.org/sqlite (pure-Go,
  no CGO).
- **tg v3 is MANDATORY — no hand-written fiber routing.** The HTTP transport
  layer MUST be **generated** by the tg v3 toolchain, NOT written by hand:
  - module: `github.com/seniorGolang/tg/v3` (the `/v3` suffix is required;
    `github.com/seniorGolang/tg` without it resolves to nothing on the proxy).
  - the `tg` CLI and the `tgp-go` plugins (`astg`, `server`) are pre-installed
    in the VM (`tg --version`, `tg pkg list` shows astg + server).
  - define the service as a Go interface annotated with `// @tg` tags in
    `contracts/`, then generate the fiber transport:
      `tg server -o internal/transport`  (NOT v2's `tg transport`, NOT hand-written routes)
  - re-run codegen after every contract change; commit the generated tree.
  - business logic (service + sqlite repository) is yours to write; only the
    HTTP wiring is generated.
- **Tests**: `go test` covering create/list/get/update/delete/toggle, and that
  data persists across a server restart (re-open the DB file).
- **Runnable**: `go run main.go` binds `0.0.0.0:8000` (all interfaces — required
  for msb port-forwarding; binding `127.0.0.1` makes the port look open but
  drops every host request). Clients reach it at `http://127.0.0.1:8000`.
