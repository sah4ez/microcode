# PRD 002: Bugfix — inline "Save" (edit) in the web UI returns 405

## Context
This is a bugfix on top of the existing Go + tg v3 todo service (PRD-001). The
service is already implemented: REST API generated by tg, SQLite storage, and a
vanilla-JS web UI in `static/`. **Do NOT rebuild or regenerate the transport** —
only the web UI's edit-save flow is broken. The image already has Go 1.26 + tg v3.

## Bug
When a user clicks "Edit" on a todo in the web UI, changes the title/description,
and clicks "Save", the request fails with **HTTP 405 Method Not Allowed**, and the
todo is not updated.

## Root cause
In `static/app.js`, the helper `asJSON(data)` hard-codes `method: "POST"`:

```js
function asJSON(data) {
  return {
    method: "POST",          // ← BUG: always POST
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify(data),
  };
}
```

`asJSON` is reused for two different operations:
- `createTodo(title, description)` → `fetchJSON("/todos", asJSON(...))` — POST is **correct** here (`POST /todos`).
- `patchTodo(id, title, description)` → `fetchJSON(\`/todos/${id}\`, asJSON(...))` — POST is **WRONG** here.

The generated transport registers `PATCH /todos/:id` for updates (NOT POST). So the
Save button sends `POST /todos/:id`, which has no matching route (only `POST /todos`
for create and `POST /todos/:id/toggle`), and fiber returns **405 Method Not Allowed**.

Direct `curl -X PATCH /todos/2` works (returns 200 + updated todo), confirming the
API is correct — only the client-side method is wrong.

## Required fix
`static/app.js` must send **PATCH** (not POST) when updating a todo:

- `patchTodo(id, title, description)` must call `fetchJSON(\`/todos/${id}\`, ...)`
  with `method: "PATCH"` and a JSON body.
- Keep `createTodo` using `method: "POST"` (unchanged — create is POST).
- Do NOT change `toggleTodo` (it correctly uses `POST /todos/:id/toggle`) or
  `deleteTodo` (correctly uses `DELETE`).

The cleanest fix is to make the HTTP method a parameter of the JSON helper rather
than hard-coding it, e.g. `asJSON(method, data)` or a small `patchJSON`/`postJSON`
pair — but any change that makes Save send PATCH and keeps Create sending POST is
acceptable.

## Scope (do NOT touch)
- `internal/transport/` — generated by tg, correct as-is. Do not regenerate.
- `contracts/` — the `Update` method already maps to `PATCH /todos/:id`. Correct.
- `internal/service/`, `internal/storage/` — unchanged.
- `main.go`, `internal/web/web.go` — unchanged (static serving works).
- `static/index.html`, `static/styles.css` — unchanged.

## Definition of done
- `go vet ./...` stays green (no Go files change, but confirm nothing broke).
- `static/app.js`: Save now sends `PATCH /todos/:id`.
- Manual verification: create a todo, click Edit, change the title, click Save →
  the todo updates (no 405); `curl -X PATCH /todos/<id> ...` → 200.
- The Create flow still works (`POST /todos` → 201) — regression check.
