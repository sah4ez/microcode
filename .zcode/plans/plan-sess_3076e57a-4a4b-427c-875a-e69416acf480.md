# Microcode — единая IaC-платформа для skillkit + loki-mode + microsandbox

## Изменение против предыдущей версии плана
**Доставка loki-mode внутрь VM:** вместо готового OCI-образа `microcode:latest` используем **стоковый `debian`-образ**, а установку всех подсистем (node, python, bun, loki-mode, skillkit CLI) делает **init-скрипт** `bootstrap.sh`, который microsandbox грузит в VM через rootfs-patch (`--copy-file`) и запускает через `msb exec`. Для кэширования установленного окружения между пересозданиями VM — `msb snapshot` (опционально, включается в манифесте).

## Суть
Greenfield-проект в пустом репо `/Users/aleksandrkozlenkov/git/microcode`. Один YAML-манифест (`platform.yaml`) декларативно описывает три аспекта разработки:
1. **Навыки** (skillkit) — какие скиллы, откуда, для какого агента переводить.
2. **Оркестрация** (loki-mode) — провайдеры, бюджет, gates, память, итерации.
3. **Среда исполнения** (microsandbox) — образ `debian`, ресурсы, сеть, секреты, тома, init-пакеты.

Python-оркестратор читает манифест и **генерирует** артефакты для каждой подсистемы (общего формата нет), затем применяет. IaC: `validate` → `plan` → `apply` → `destroy`.

## Архитектура потока

```
platform.yaml (единый IaC-источник)
        │
  microcode CLI (Python): read → validate → plan → apply
        │
        ├─→ [skills]   генератор → .skills → skillkit install/translate
        │               → SKILL.md в skills/ (примонтирован в VM)
        ├─→ [loki]     генератор → loki-config.yaml + .env → LOKI_CONFIG_FILE
        └─→ [sandbox]  генератор → msb create debian
                        + bootstrap.sh (rootfs-patch) → msb exec install
                        + опц. msb snapshot → msb exec loki start
```

Принцип: манифест — единственный источник правды; подсистемы получают сгенерированные подмножества.

## Файл bootstrap.sh (центральное изменение)

Инсталлирует окружение внутри `debian` VM. Генерируется оркестратором из секции `sandbox.packages` манифеста (можно переопределять), запускается один раз через `msb exec`. Содержит:
```bash
#!/bin/bash
set -e
# системные пакеты
apt-get update && apt-get install -y curl git ca-certificates
# node (через NodeSource) + bun
curl -fsSL https://deb.nodesource.com/setup_22.x | bash - && apt-get install -y nodejs
curl -fsSL https://bun.sh/install | bash
# python3 (уже есть в debian, добавляем pip)
apt-get install -y python3 python3-pip python3-venv
# подсистемы
npm install -g loki-mode @skillkit/cli
# claude code CLI (для провайдера claude) — если включён в манифесте
echo 'export PATH="$HOME/.bun/bin:$PATH"' >> ~/.bashrc
```
Параметризуется манифестом: версии, какие CLI ставить (`loki`, `skillkit`, опционально `claude`/`codex`), кастомные apt/npm-пакеты.

## Схема `platform.yaml` (с обновлённой секцией sandbox)

```yaml
version: 1
project:
  name: my-app
  workdir: /workspace
  state_dir: .microcode

skills:                          # → skillkit
  registry:
    sources: [anthropics/skills]
  install:
    - { source: anthropics/skills, skills: [code-review], agents: [claude-code] }
  translate:
    target_agent: claude-code
    output_dir: skills
    also_into_memory: true

loki:                            # → loki-mode config
  provider: claude
  max_iterations: 20
  max_budget_usd: 10.0
  effort: high
  sdk_mode: full
  quality_gates: { enabled: true, opt_out: [] }
  memory: { enabled: true, managed: true }
  proofs: { enabled: true }

sandbox:                         # → microsandbox
  image: debian                  # ★ стоковый образ (НЕ кастомный)
  tag: bookworm-slim
  name: loki-build
  cpus: 2
  memory: 2048
  max_cpus: 4
  max_memory: 8192
  network:
    profile: [public]            # egress для apt/npm/pip; добавить host если нужен хост
    deny_domains: []
  init:                          # ★ новая подсекция: что ставит bootstrap.sh
    packages:
      apt: [curl, git, ca-certificates, python3, python3-pip]
      npm_global: [loki-mode, "@skillkit/cli"]
      bun: true
      node_version: "22"
      extra_shell: ""            # доп. inline-команды в конец bootstrap.sh
    snapshot:                    # кэш установленного окружения
      enabled: false             # true → после bootstrap делает msb snapshot, переиспользует
      name: loki-prepared
  secrets:
    - env: ANTHROPIC_API_KEY
      allow_hosts: [api.anthropic.com]   # ключ НЕ входит в VM, подмена на границе
  volumes:
    - { name: loki-data, dest: /data }
  mounts:
    - { host: ./src, dest: /workspace, readonly: false }
  ports: [57374:57374]
  env: {}
```

## Команды CLI

| Команда | Что делает |
|---|---|
| `microcode validate [file]` | pydantic + JSON Schema валидация |
| `microcode plan [file]` | Сгенерировать артефакты в `.microcode/`, вывести упорядоченный план (dry-run) |
| `microcode apply [file]` | Выполнить план (см. порядок ниже) |
| `microcode destroy [file]` | `msb stop`/`rm`, чистка стейта |
| `microcode show [file]` | Резолвнутое состояние человекочитаемо |
| `microcode doctor` | Проверка наличия `msb`, `skillkit` на хосте + версий |

## Порядок apply (детерминированный, с init-скриптом)

1. **Валидация окружения** — `msb`, `skillkit` присутствуют на хосте (`doctor`-проверка).
2. **Генерация артефактов** в `.microcode/`: `loki-config.yaml`, `.env`, `.skills`, **`bootstrap.sh`** (из `sandbox.init`).
3. **skillkit (на хосте)** — `skillkit manifest install --yes` → `skillkit translate --all --to <target> -o skills/`. Скиллы в `./src/skills/` (видны из VM через mount).
4. **msb create** — `msb create debian:bookworm-slim --name <name> --cpus .. -m .. --net public --copy-file ./.microcode/bootstrap.sh:/root/bootstrap.sh [секреты/тома/порты]`. Скрипт инжектируется в rootfs до загрузки.
5. **init (внутри VM)** — `msb exec <name> -- bash /root/bootstrap.sh`. Ставит node/bun/python + loki-mode + skillkit. Запускается от root (дефолт debian).
6. **(опц.) snapshot** — если `init.snapshot.enabled`: `msb stop <name>` → `msb snapshot create <snap> --from <name>`; при следующем apply стартует из `from_snapshot=<snap>`, пропуская шаг 5.
7. **loki start (внутри VM)** — `msb exec <name> -- bash -lc 'loki start --config /workspace/.microcode/loki-config.yaml --no-dashboard "$PRD"'`. Конфиг и скиллы доступны через mount.

## Ключевые проектные решения

- **Стоковый debian + init-скрипт** вместо кастомного образа: быстрее итерация манифеста (без пересборки), меньше lock-in на сборку, использует нативный rootfs-patch microsandbox.
- **bootstrap.sh генерируется** из `sandbox.init` (версии, пакеты, CLI подсистем) — управляется манифестом, а не захардкожен.
- **snapshot-кэш опционален**: повторный `apply` без re-install, если включён в манифесте.
- **Манифест публичный, секреты вне его.** Ключи по имени env-переменной; реальные значения из хост-окружения прокидываются через `msb --secret ENV@host` (ключ не входит в VM, подмена TLS-прокси на границе для allow-listed хостов).
- **Генераторы — чистые функции** (манифест → строки/объекты), тестируемые без запуска. Runners — тонкие обёртки над CLI подсистем.
- **Dry-run первым классом** (`plan`, `apply --dry-run` показывают все команды до выполнения).
- **Скиллы в один формат** (по умолчанию `claude-code` → `SKILL.md`) для единообразного подхвата loki.

## Соответствие требованиям

| Требование | Где закрывается |
|---|---|
| Скиллы skillkit загружаются в loki | `generators/skills.py` + mount `skills/` в VM |
| loki работает внутри microVM | `sandbox_runner` (msb create+exec) + bootstrap.sh + `loki_runner` |
| Всё в microsandbox | единый `apply` поднимает VM, init, запускает loki |
| 3 аспекта в одном месте | три подсекции манифеста + три генератора |
| Единая конфигурация | `platform.yaml` |
| IaC-подход | validate/plan/apply/destroy, детерминизм, dry-run, stateless-генерация |
| stock debian + init-скрипт | `sandbox.image: debian` + `sandbox.init` + `generators/bootstrap.py` |

## Объём реализации (MVP)
Полная рабочая платформа: pydantic-схема + JSON Schema, генераторы (вкл. bootstrap.sh), runners (вкл. rootfs-patch + snapshot), typer-CLI, шаблоны, примеры (minimal + full-stack), ARCHITECTURE.md, тесты (генераторы на снапшоты, валидация, детерминизм плана). CLI реально вызывает `skillkit`/`msb`/`loki`.

## Что НЕ входит в MVP
- Свой MCP-сервер-обёртка (выбран генератор файлов).
- Автоустановка `msb`/`skillkit` на хост — проверяются `doctor`.
- Управление версиями подсистем (параметризуются в манифесте).
- Параллельная установка нескольких провайдеров loki одновременно.

## Проверка готовности
- `microcode validate examples/minimal.yaml` → exit 0.
- `microcode plan examples/minimal.yaml` печатает все msb/skillkit команды + показывает сгенерированный `bootstrap.sh` без выполнения.
- `microcode apply examples/minimal.yaml` (с установленными подсистемами) поднимает debian-VM, ставит окружение, запускает loki.
- `tests/` зелёные; генераторы дают эталонные артефакты; план детерминирован.
